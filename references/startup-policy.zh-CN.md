# 启动项优化策略

## 检查范围

- 用户与全局启动文件夹。
- HKCU/HKLM 的 `Run`、`RunOnce`，包括 WOW6432Node。
- Run 项和启动文件夹快捷方式的 `StartupApproved` 状态。
- 登录或开机触发的计划任务。
- Windows 系统目录之外的自动服务。
- 使用 Windows“启动应用”界面时，需要同时核对 UWP/Store 应用。

## 状态判断

`Win32_StartupCommand` 能列出配置项，但不能单独证明项目当前启用。必须结合 `StartupApproved`：

- 首字节通常为 `02`：启用。
- 首字节通常为 `03`：禁用。
- 没有覆盖值：属于已配置但应在 Windows 设置或任务管理器中再次确认的条目。

不能只因为服务是 `Automatic` 就判定它拖慢启动。还要检查：

- 当前是否运行。
- 是否延迟启动。
- 是否有其他进程或服务依赖它。
- 当前硬件或软件是否仍需要它。
- 能否测到持续 CPU、GPU 或内存占用。

## 建议分类

### 通常可关闭

- 仅用于更新或托盘的辅助程序。
- 无需每次登录都运行的游戏启动器、动态壁纸。
- 软件卸载后留下的不存在程序入口。
- 用户确认不需要登录即启动的云盘、远控、VPN/代理、模拟器和开发数据库服务。

### 通常保留

- Windows 安全和 Defender 服务。
- 音频、网络、存储、显示、输入、功耗和散热控制服务。
- 笔记本控制中心的风扇和性能模式服务。
- 正在使用授权软件的许可证服务。

### 优先使用 Manual 而不是 Disabled

用户以后还会使用时：

1. 如允许，立即停止服务。
2. 把 `StartType` 改为 `Manual`。
3. 只删除不必要的托盘或启动入口。
4. 保留安装文件、配置、数据和 service 注册。

某些受保护服务会显示 `NOT_STOPPABLE`。若启动类型已经改为 `Manual`，应告知用户：当前实例只能在关机或重启后结束，但下次不会自动启动。

## 验证

修改服务或启动项前，必须输出带编号的审阅清单，等待用户的一次 `确认` 或明确编号。清单要说明每项属于必需、场景相关、失效还是可安全关闭。收到授权后，不得对同一批项目再次询问。检查后新增的项目不得直接混入执行，必须重新审阅。

报告：

- 项目及机制：Run、启动文件夹、计划任务或服务。
- 启用、禁用或手动状态。
- 程序路径是否存在。
- 能测到时的当前进程数与内存。
- 是否属于硬件或软件运行所需依赖。

修改后重新检查服务 `Status`、`StartType`、启动项/计划任务状态和进程状态。
