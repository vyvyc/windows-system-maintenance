# 磁盘清理策略

## 分类

| 类型 | 示例 | 默认处理 |
|---|---|---|
| 可重新生成缓存 | 浏览器 HTTP/代码/着色器缓存、更新器下载、包管理器缓存 | 确认相关程序已关闭后可清理 |
| 需重建缓存 | Gradle 缓存、IDE 索引、模型缓存 | 可以清理，但下次使用可能需要重新下载或长时间重建 |
| 安装介质 | ISO、ZIP、已解压安装包 | 仅在用户确认不再安装或修复时删除 |
| 用户数据 | 文档、桌面文件、录像、虚拟机、项目、数据集 | 普通“清理”请求不得删除，必须给出明确路径 |
| 受保护系统数据 | `WinSxS`、`Windows\Installer`、pagefile、系统包存储 | 禁止手动删除 |

用户表示以后还会使用软件时，优先把服务改为 `Manual`，不要设为 `Disabled`。

## 证据要求

- 所有固定卷的容量与剩余空间。
- 顶层目录大小和文件数。
- 识别虚拟机磁盘、录像、ISO、压缩包时列出大文件。
- 检查 ZIP 是否与已解压目录重复时读取压缩包成员名称。
- 缓存和安装包的修改时间。
- 删除应用程序缓存前检查相关进程。
- 删除软件目录前检查当前产品注册状态。

测量值按“实际观察”报告，预计释放空间必须标注为估算。

## 删除流程

1. 把每个用户选定目标解析为绝对路径。
2. 检查是否为重解析点；除非只删除链接，否则不要跟随。
3. 确认目标不是无关数据的父目录。
4. 只停止占用目标的应用或服务。
5. 给每个目标分配审阅编号，并标记为 `可执行`、`需要决定`、`受保护` 或 `拒绝执行`。
6. 输出审阅清单，等待用户回复 `确认` 或明确编号。
7. 执行前再次验证选中的目标。
8. 该单次授权覆盖整个选中批次，不得逐项再次询问。
9. 精确删除用户列出的目录和文件，禁止对盘符根目录或大范围通配符执行删除。
10. 仅暂停自启动时，保留配置文件、数据库和用户数据。
11. 删除后逐个验证目标，并报告被占用的残留文件。

批量删除时维护 `{标签, 绝对路径}` 列表并逐项执行。禁止使用 `Remove-Item "$env:USERPROFILE\*"` 这类模糊命令。

## Windows 注意事项

- 用 `DISM /Online /Cleanup-Image /AnalyzeComponentStore` 做只读分析，获准后再使用受支持的组件清理。
- 不删除 `Windows\Installer`，修复和卸载依赖它。
- 不删除 `C:\ProgramData\Package Cache`，安装器可能需要它。
- 不把 `pagefile.sys`、`swapfile.sys` 当作普通垃圾处理。
- 不把 `.vscode\extensions` 当作缓存；应审阅或卸载扩展。
- 清理浏览器缓存时，不删除书签、密码、Cookie、用户配置或扩展数据，除非用户明确要求。
- 清理 GPU 驱动更新缓存前，确认当前没有正在安装的更新。
- 对重复 ZIP，先比较压缩包成员与解压目录内容，再建议删除。

## 厂商卸载注意事项

- 同时查询 64 位与 WOW6432Node 卸载注册表。
- 使用 `WindowsInstaller.Installer.ProductState()` 判断 MSI 产品是否仍已安装。
- 启动卸载器前停止已知的厂商服务。
- Windows Installer 串行执行；上一个事务处于挂起状态时不要继续启动另一个卸载。
- “卸载器成功启动”不等于产品已删除。
- 遇到必须人工操作的提权界面时，应交给用户或使用已经验证过的静默参数。
- 完成后重新验证产品状态、残留注册表、文件与重启要求。
